# Question 3: Secure File Processing with Linux System Calls

## Design Overview

The `employee_records.c` program performs all file operations using low-level Linux system calls instead of standard C file functions such as `fopen()` or `fprintf()`. It uses `open()`, `read()`, `write()`, `lseek()`, and `close()` to create a binary file, store fixed-size employee records, modify a specific record directly within the file, and retrieve records from any position without rewriting the entire file.

---

## Commands Executed and Their Purpose

### `gcc employee_records.c -o employee_records`

Compiled the source code into an executable named `employee_records`. The program relies on Linux system calls for file handling rather than buffered stdio functions.

### `./employee_records`

Executed the program.

The output confirmed the following operations:

* **Three employee records** (Alice, Bob, and Carol) were successfully written to the binary file.
* The second record (index **1**) was updated in place by replacing **Bob** with **Bobby** and changing the salary to **47000.00**, without modifying the other records.
* Reading the file after the update displayed:

  * Record 0 – Alice / 50000.00
  * Record 1 – Bobby / 47000.00
  * Record 2 – Carol / 60000.00

This verified that only the intended record was changed while the remaining records stayed unchanged.

### `od -c employees.dat | head -20`

Since `xxd` was unavailable in the working environment, the `od -c` command was used to inspect the binary file.

The output displayed the raw contents of `employees.dat`, showing three fixed-size records stored sequentially. The second record contained the updated name **"Bobby"**, confirming that the modification occurred directly within the file rather than by recreating or rewriting it.

## Explanation of the System Calls Used

### `open()`

The file is opened using the flags `O_CREAT | O_RDWR | O_TRUNC`.

* `O_CREAT` creates the file if it does not already exist.
* `O_RDWR` opens the file for both reading and writing.
* `O_TRUNC` clears any existing file contents before new data is written.

This provides precise control over how the file is created and accessed.

### `write()`

The `write()` system call stores the raw bytes of each employee record directly into the file at the current file offset. Unlike buffered stdio functions, the program has complete control over when data is passed to the operating system.

### `lseek()`

`lseek()` enables direct access to any record by moving the file pointer to:

`record_index × RECORD_SIZE`

This allows the program to update or read a specific record without scanning the entire file, making random access efficient.

### `read()`

The `read()` system call retrieves one complete employee record from the current file position into memory. Since every record has a fixed size, records can be accessed quickly using their calculated offsets.

### `close()`

After all operations are completed, `close()` releases the file descriptor and ensures that any pending data is properly written before the program exits.

Together, these system calls provide efficient low-level file management, allowing direct record access, in-place updates, and precise control over file operations—features that are more cumbersome to implement using stream-based stdio functions.
